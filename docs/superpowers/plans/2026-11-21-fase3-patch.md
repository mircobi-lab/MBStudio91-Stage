# MBStudio91 Stage — Fase 3: patch, Launchpad, tempo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Libreria di 8 banchi × 64 patch richiamabili dalla Launchpad Mini MK1 e dallo schermo, cambio patch senza buchi audio né note appese, tempo libero/tap o da MIDI clock esterno passato ai plugin, limitatore di sicurezza sul master.

**Architecture:** Logica pura e testata in unità piccole (`Patch`/`Library`, `TempoTracker`, `LaunchpadMapping`); `Station` passa da una catena a due (attiva + in coda); un `PatchManager` sul message thread cattura e richiama le patch usando una fabbrica di istanze iniettabile (vera = `PluginCatalog`, nei test = finti) e un pool di istanze già caricate; `LaunchpadController` gestisce il dispositivo.

**Tech Stack:** C++17, JUCE 8.0.15 (`juce_dsp::Limiter`), CMake, Actions `macos-15-intel`, `juce::UnitTest`.

**Spec:** `docs/superpowers/specs/2026-11-21-mbstudio91-stage-design.md` (2.4–2.6, 2.10, 5.1, 5.2, 5.4, 5.5, 5.7, 7 fase 3)

## Global Constraints

- Vincoli delle fasi 1–2 invariati.
- Libreria: **8 banchi (A–H) × 64 patch**; file `~/Music/MBStudio91 Stage/libreria.xml`; copia `libreria-AAAA-MM-GG.xml` a ogni avvio (una per giorno).
- Patch per postazione: strumento + ≤3 effetti come ID portabile + stato (`getStateInformation`, base64), volume dB, mute, `KeyZone`. Più il nome della patch. Il tempo NON è nella patch (spec 2.10, globale).
- Richiamare una patch ricarica sempre lo stato salvato; i ritocchi segnano la patch "modificata" e vanno nella libreria solo con SALVA.
- Cambio patch: note nuove alla catena nuova, note tenute e pedale restano sulla vecchia; la vecchia, quando non ha più note né pedale, suona la coda per **3 s** poi sfuma in **100 ms** e viene liberata sul message thread. Un nuovo cambio mentre c'è già una catena in coda la chiude con sfumatura di 20 ms.
- Plugin già nel pool: patch pronta entro ~100 ms; altrimenti caricamento asincrono e LED rosso lampeggiante. Pool: massimo **4** istanze inattive per postazione, le più vecchie distrutte.
- Plugin mancante in una patch: quella postazione resta vuota con messaggio d'errore, le altre si caricano.
- Launchpad Mini MK1 (protocollo "classico", X-Y): nota griglia = 16·riga + colonna (riga 0 in alto, colonne 0–7); colonna 8 = tasti tondi a destra; tasti tondi in alto = CC 104–111. Colore = velocity `16·verde + rosso + 12` (normale), `+8` invece di `+12` per lampeggio con `B0 00 28` attivo; reset `B0 00 00`. Colori: spento 12, rosso 15, verde 60, ambra 63, rosso lampeggiante 11. Da verificare sul dispositivo.
- Funzioni Launchpad: griglia = 64 patch del banco attivo; tondi in alto = banchi A–H; destra 1–4 = mute postazioni; 5 = patch precedente; 6 = successiva; 7 = TAP (lampeggia a tempo); 8 = PANIC tenendolo premuto **500 ms**.
- LED griglia: spento = vuota, ambra = salvata, verde = attiva, rosso lampeggiante = in caricamento. Banchi: verde = attivo, ambra = contiene patch, spento = vuoto. Mute attivo = rosso.
- Tempo globale INT/EXT: INT = BPM manuale (20–300, predefinito 120) e tap (media degli ultimi 4 intervalli, reset dopo 2 s di pausa); EXT = MIDI clock (24 ppq) da un ingresso scelto, media mobile su 24 impulsi, Start/Stop/Continue/SPP; senza clock per 2 s resta l'ultimo BPM e lo segnala. I plugin ricevono BPM e posizione tramite `AudioPlayHead`; in INT il trasporto è sempre "in riproduzione".
- Limitatore master: `juce::dsp::Limiter`, soglia −1 dB, rilascio 100 ms, dopo il volume master.

## Review Focus

1. **Cambio patch con note e pedale tenuti**: le note tenute finiscono sulla catena vecchia (note-off e CC64 su lì), nessuna nota appesa. → Task 2.
2. **Due cambi di patch in rapida successione** (il secondo mentre il primo sta caricando o una catena è in coda): resta la patch dell'ultimo pad premuto, nessun crash né doppio suono. → Task 3.
3. **Patch che contiene un plugin disinstallato**: le altre postazioni si caricano, l'errore è visibile. → Task 3.
4. **Launchpad scollegata e ricollegata**: torna a funzionare con i LED aggiornati. → Task 4 (verifica manuale), mappatura in test.
5. **Clock esterno che si ferma o arriva irregolare**: il BPM resta stabile e non crolla a 0. → Task 5.

### Task 1: Patch e Library

**Interfaces — Produces:**
```cpp
struct PluginSlot { juce::String portableId, name; juce::MemoryBlock state; };   // portableId vuoto = slot vuoto
struct StationPatch { PluginSlot instrument; std::array<PluginSlot, 3> effects; float gainDb = 0; bool muted = false; KeyZone zone; };
struct Patch { juce::String name; std::array<StationPatch, 4> stations;
               juce::ValueTree toValueTree() const; static Patch fromValueTree (const juce::ValueTree&); };
class Library {
public:
    static constexpr int numBanks = 8, patchesPerBank = 64;
    const std::optional<Patch>& get (int bank, int index) const;
    void set (int bank, int index, Patch);  void clear (int bank, int index);
    void rename (int bank, int index, const juce::String&);
    bool bankHasPatches (int bank) const;
    std::optional<std::pair<int,int>> neighbour (int bank, int index, int direction) const; // prossima patch salvata (±1), anche attraverso i banchi, ciclica; nullopt se libreria vuota
    juce::ValueTree toValueTree() const;  void fromValueTree (const juce::ValueTree&);
    bool saveTo (const juce::File&) const;  bool loadFrom (const juce::File&);
    static juce::File dailyBackupFor (const juce::File& libraryFile, juce::Time); // libreria-AAAA-MM-GG.xml
};
```

### Task 2: Station a due catene

**Interfaces — Produces (Station):**
```cpp
struct Chain { std::unique_ptr<juce::AudioPluginInstance> instrument; std::array<std::unique_ptr<juce::AudioPluginInstance>, 3> effects; };
void setChain (Chain);                 // message thread: la catena attiva va in coda, quella in coda (se c'e') sfuma in 20 ms
std::vector<std::unique_ptr<juce::AudioPluginInstance>> takeFinishedInstances(); // message thread: istanze della coda terminata (gia' avvisate con onBeforeInstanceRemoved)
bool hasTailChain() const;
static constexpr double tailSeconds = 3.0;
```
- Instradamento in `renderAdd`: note-on → attiva; note-off → la catena il cui NoteTracker ha la nota (prima la coda), altrimenti attiva; CC64 e pitch bend → entrambe; altri messaggi → attiva. La coda conta i 3 s solo quando non ha note né pedale; poi rampa 100 ms e si segna finita. Entrambe le catene processano e si sommano.
- `setInstrument/setEffect` restano (modificano la catena attiva, senza coda). `prepare` ripara entrambe. `requestPanic` vale per entrambe.
- Tests: nota tenuta prima di `setChain` → il note-off arriva al vecchio strumento, il nuovo riceve la nota successiva; con pedale tenuto la coda non scade finché CC64=0; dopo 3 s + 100 ms di blocchi senza note la coda è finita e `takeFinishedInstances` restituisce le istanze e il suono vecchio è a zero; secondo `setChain` con coda presente → la coda vecchia finisce entro 20 ms; panic silenzia entrambe.
- **Commit** `feat: cambio di catena senza interruzioni con coda di 3 secondi`

### Task 3: PatchManager e pool di istanze

**Interfaces — Produces:**
```cpp
class PatchManager : private juce::Timer {
public:
    using InstanceFactory = std::function<void (const juce::String& portableId, double sr, int bs,
                                                std::function<void (std::unique_ptr<juce::AudioPluginInstance>, juce::String error)>)>;
    PatchManager (StageEngine&, Library&, InstanceFactory);
    Patch capture (const juce::String& name) const;          // stato attuale delle 4 postazioni
    void recall (int bank, int index);                       // asincrono; l'ultimo richiamo vince
    void saveCurrentTo (int bank, int index, const juce::String& name);
    int activeBank() const;  int activePatch() const;  bool isLoading() const;  bool isModified() const;
    void setActiveBank (int);  void markModified();
    std::function<void()> onStateChanged;                     // message thread
    juce::StringArray lastErrors() const;
};
```
- La fabbrica vera usa `PluginCatalog::findByPortableId` + `createInstanceAsync`; nei test una fabbrica finta crea `FakeInstrument` / `FakeGainEffect` (con stato salvabile) o restituisce errore per ID sconosciuti.
- Richiamo: per ogni postazione prende le istanze dal pool (stesso ID) o dalla fabbrica; quando sono tutte pronte (o fallite) applica `setStateInformation`, `setChain`, volume, mute, zona; se nel frattempo è stato richiesto un altro richiamo, i risultati del vecchio vanno nel pool e si applica solo l'ultimo (generazione).
- Pool: istanze restituite da `takeFinishedInstances` (timer 10 Hz) e da richiami superati; max 4 per postazione, si scartano le più vecchie; il pool viene ripreparato con la postazione.
- Modificata: `AudioProcessorListener` sulle istanze attive + `markModified()` dalla UI; si azzera a richiamo e a salvataggio.
- Tests: cattura → salva → richiama ripristina stati, zone, volume, mute; plugin sconosciuto → postazione vuota, errore in `lastErrors`, altre caricate (Review Focus 3); due `recall` di fila con fabbrica lenta (callback ritardati) → applicata solo l'ultima (Review Focus 2); secondo richiamo dello stesso strumento usa il pool (la fabbrica non viene chiamata); parametro cambiato → `isModified()`.
- **Commit** `feat: richiamo delle patch con pool di istanze`

### Task 4: Launchpad Mini MK1

**Interfaces — Produces:**
```cpp
namespace LaunchpadMapping {
  enum class ActionType { none, patch, bank, mute, previous, next, tap, panicDown, panicUp };
  struct Action { ActionType type = ActionType::none; int index = 0; };
  Action decode (const juce::MidiMessage&);              // solo pressioni (velocity>0) tranne panicUp
  enum class Led { off, red, green, amber, redFlash };
  int velocityFor (Led);                                 // 12, 15, 60, 63, 11
  struct State { int bank = 0; int activePatch = -1; int loadingPatch = -1;
                 std::array<bool, 64> occupied {}; std::array<bool, 8> bankOccupied {}; std::array<bool, 4> muted {}; bool tapLit = false; };
  std::vector<juce::MidiMessage> ledMessages (const State&, const State* previous); // solo i LED cambiati se previous != nullptr
  std::vector<juce::MidiMessage> initMessages();         // reset, layout X-Y, lampeggio automatico
}
class LaunchpadController : private juce::Timer, private juce::MidiInputCallback { /* apre il primo dispositivo con "Launchpad" nel nome, hot-plug, invia LED a 20 Hz se cambiati, PANIC dopo 500 ms */ };
```
- Tests mappatura: nota 0 → patch 0; nota 0x77 (riga 7, col 7) → patch 63; nota 8 → mute 0; 24,40,56 → mute 1–3; 72 → previous; 88 → next; 104 → tap; 120 → panicDown e il rilascio → panicUp; CC 104 → bank 0, CC 111 → bank 7; velocity 0 su griglia → none; `velocityFor`; `ledMessages` con patch attiva/occupata/in caricamento e con `previous` (solo differenze); `initMessages` contiene `B0 00 00`.
- **Commit** `feat: Launchpad Mini MK1 per banchi, patch, mute, tap e PANIC`

### Task 5: Tempo

**Interfaces — Produces:**
```cpp
class TempoTracker {
public:
    enum class Source { internal, external };
    void setSource (Source);  Source getSource() const;
    void setBpm (double);     // 20..300, solo INT
    void tap (double nowSeconds);
    void handleClockMessage (const juce::MidiMessage&, double nowSeconds); // 0xF8, Start, Stop, Continue, SPP
    double getBpm() const;  bool isPlaying() const;  bool isClockLost (double nowSeconds) const;
    void advance (int numSamples, double sampleRate);   // thread audio: avanza la posizione
    juce::AudioPlayHead::PositionInfo position() const;
};
class StagePlayHead final : public juce::AudioPlayHead { /* restituisce TempoTracker::position() */ };
```
- Engine: `TempoTracker& tempo()`, `setClockSource (deviceId)`, i messaggi clock dall'ingresso scelto vanno al tracker prima dell'instradamento; `setPlayHead` su tutte le istanze (anche quelle create dopo, in `Station::prepareInstance`).
- Tests: tap 4 volte a 0.5 s → 120; pausa di 3 s poi tap → nessun salto; 24 clock a intervalli di 1/48 s → 120 ±0.5; jitter ±10% → 120 ±2; Stop → `isPlaying()` false, Start → true e posizione 0; SPP 16 → ppq 4; nessun clock per 2 s → `isClockLost` true e BPM invariato (Review Focus 5); `advance` di 48000 campioni a 120 BPM → ppq +2.
- **Commit** `feat: tempo libero, tap e MIDI clock esterno ai plugin`
